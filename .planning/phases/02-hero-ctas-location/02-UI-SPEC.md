# Phase 02 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind components, following the reference implementations already in `src/components/layout/Header.tsx` and `src/components/layout/Footer.tsx` |
| Icon library | none — see "Icons" note below |
| Font | Display: **Anton** (`--font-display`, weight 400 only, Archivo Black fallback) · Body: **Manrope** (`--font-body`, variable 200–800, restricted to 400/600 in this contract) · both self-hosted via `next/font/google`, bound in `src/app/layout.tsx` |

**shadcn gate — decision recorded without an interactive prompt.** No `components.json` exists and
the stack is Next.js/React, which normally triggers the shadcn init question. This research run
had no interactive channel back to the developer, so it defaults to **`Tool: none`** rather than
blocking, on this evidence:

1. `.claude/CLAUDE.md`'s own tech-stack research gates even `clsx`/`tailwind-merge` behind "only if
   component variants get non-trivial... don't add it speculatively" — shadcn (Radix + a CLI +
   generated component files) is a heavier addition than either.
2. Phase 2's UI is five largely-static Server Component sections (hero, CTAs, brand story,
   location, FAQ) with exactly one small interactive surface (disabled/pending CTA state) — no
   dialogs, dropdowns, forms, or data tables that would justify a component library.
3. The only components built so far (`Header.tsx`, `Footer.tsx`, the walking-skeleton CTA in
   `src/app/page.tsx`) are hand-rolled Tailwind against the brand's own design tokens — introducing
   shadcn now would create two competing component idioms mid-project.

**This is a default, not a locked decision** — if the developer wants shadcn initialized, say so
before or during plan-phase/execute-phase and re-run this research step; nothing downstream
depends on `Tool: none` in a way that resists changing it later.

**Icons.** No icon library is installed and none is recommended for this phase. The tone-of-voice
guide's accessibility rule (§6: "nenhum significado depende só de emoji" / every link names its own
destination) means none of this phase's three CTAs need a decorative icon to be understood. Where a
purely decorative mark earns its place (e.g. a map-pin glyph next to "Como chegar", a chevron on
the FAQ `<details>` marker), hand-author a minimal inline SVG in the brand's own line-art style
(`docs/brand-guidelines.md` → "Ilustração de alho em line-art") and mark it `aria-hidden="true"` —
never introduce a generic icon package (lucide, heroicons, etc.) for a handful of one-off marks.

Component Inventory section omitted per template — not applicable when `Tool: none`.

## Spacing Scale

Declared values (multiples of 4 — already the project's convention, no phase override):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge padding |
| sm | 8px | Compact element spacing (CTA row gap, chip padding) |
| md | 16px | Default element spacing (section internal padding, mobile page gutter) |
| lg | 24px | Section padding on larger viewports, gap between hero elements |
| xl | 32px | Layout gaps between major hero sub-blocks |
| 2xl | 48px | Vertical gap between the five homepage sections (Hero/CTAs/Marca/Localização/FAQ) |
| 3xl | 64px | Top/bottom page-level padding on wide viewports |

Exceptions:

- **44px minimum touch target** on every tappable CTA (button, link styled as a button, the FAQ
  `<details>`/`<summary>` marker) — WCAG 2.5.5, required by PERF-01's "navegação por teclado, foco
  visível" umbrella even though this project doesn't track SC 2.5.5 by number. 44 is itself a
  multiple of 4, so this is a floor on top of the scale, not a break from it.

## Typography

All four roles reuse the exact `--text-*` tokens already declared in
`src/styles/design-tokens.css` (MARCA-03) — this phase does not introduce a new size.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--text-body`), `font-body` (Manrope) | 400 (regular) | 1.5 |
| Label | 14px (`--text-body-sm`), `font-body` (Manrope) | 600 (semibold) | 1.5 |
| Heading | 24px (`--text-heading-2`), `font-display` (Anton) | 400 (Anton has no other weight) | 1.2 |
| Display | 32px (`--text-heading-1`), `font-display` (Anton) | 400 (Anton has no other weight) | 1.2 |

Two weights only, both from Manrope's variable axis: **400 regular** for all body copy, **600
semibold** for CTA labels, badges, the "provisório" tag, and FAQ question text. Anton ships one
weight (400) by design (MARCA-03) — do not simulate a bold Anton with `font-weight` overrides.

Sub-role note (reused, not a new size): `--text-heading-3` (20px, same family/weight/line-height as
Heading) is reserved for FAQ question titles when they're rendered as a level below the section's
own H2 — this is the existing token, used exactly as `docs/brand-guidelines.md` already documents
it, not a fifth size invented for this phase.

Content-fit rule (tone-of-voice.md §3, carried into this contract as a hard constraint): all three
hero CTA labels ("Ver cardápio", "Pedir no iFood", "Como chegar") and the hero headline must fit a
360px-wide mobile viewport without wrapping past two lines at the Display/Label sizes above.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-surface-deep` `#000000` (Preto) | Hero section background, page's outer `<body>` background (already set in `layout.tsx`) |
| Secondary (30%) | `--color-surface-primary` `#202526` (Carvão) | Brand-story, Localização, and FAQ section backgrounds (alternating with Preto per `docs/brand-guidelines.md`'s "variação de seção"); footer (already built) |
| Accent (10%) | `--color-accent` `#B8FF00` (Verde-limão) | Reserved for: (1) the primary/secondary CTA button fills ("Pedir no iFood", WhatsApp CTA, "Ver cardápio" border+text); (2) the global `:focus-visible` ring (already implemented, `globals.css`); (3) the hero's kicker/tagline line ("Mais que um pão de alho!") rendered `font-display text-accent uppercase`, matching the existing pattern in `Footer.tsx`'s store-name line; (4) small line-art accent strokes inside the hero's garlic illustration. Never a full section background (brand-guidelines.md: "uma página inteira em lima... é ilegível"). |
| Destructive/Alert | `--color-accent-coral` `#FF3B30` (Coral) | Reserved for exactly one use in this phase: the INTEGRA-03 "iFood indisponível" notice text/icon. No destructive (delete/cancel) actions exist in this phase — see Copywriting Contract. Use coral text on `--color-surface-deep`, never on Carvão (contrast table: Coral/Carvão fails 4.5:1 for body text). |

Additional brand color used outside the 60/30/10 roles (documented in `docs/brand-guidelines.md`,
not a new token): `--color-accent-olive` `#7D804D` (Oliva) is reserved for the "provisório" badge
— the hours notice (LOCAL-03) and the hero's "imagem ilustrativa" disclosure tag (D-03) — as
Oliva's documented role ("acento terroso secundário") reads as neutral/pending rather than
Coral's "alerta/urgência," which stays reserved for the one real unavailability notice above.
Use Oliva on `--color-surface-deep` for badge text (contrast table: Oliva/Preto passes AA at
≈5.1:1; Oliva/Carvão fails), or as a bold/large-text badge label if placed on Carvão.

CTA fill rule carried from `docs/brand-guidelines.md` (do not re-derive): text on a lime-filled
button is always `--color-surface-deep` or `--color-surface-primary` — **never white**.

## Copywriting Contract

Exact CTA labels below are already locked (HERO-02, `src/content/skeleton.ts`) — this contract
does not re-open them, only assigns visual hierarchy and states.

| Element | Copy |
|---------|------|
| Primary CTA (filled accent, when `confirmed: true`) | "Pedir no iFood" — same filled-accent treatment applies verbatim to the WhatsApp CTA per D-06 (no separate label text specified here; WhatsApp's own label is set by whoever writes its final copy, same visual weight as iFood) |
| Secondary CTA (accent-outline) | "Ver cardápio" |
| Tertiary CTA (underlined text link, same style as `Footer.tsx`'s Instagram link) | "Como chegar" |
| Pending/disabled CTA state (D-05, applies to both iFood and WhatsApp while `confirmed: false`) | "{Ação} (em breve)" — e.g. "Pedir no iFood (em breve)" — never a bare disabled label with no explanation, never a live-looking link to the placeholder URL |
| INTEGRA-03 unavailability notice (coral, problem + working next step) | "Pedido pelo iFood chegando em breve — enquanto isso, dá uma olhada em como chegar até a loja." (points to the "Como chegar" CTA, which is a confirmed, working Maps link — not to the not-yet-built cardápio route; see UI Considerations, unresolved row) |
| Empty state heading (LOCAL-03, empty `hours.schedule`) | "Horário de funcionamento" |
| Empty state body (LOCAL-03) | "Em atualização — confirme no iFood ou no WhatsApp antes de vir." |
| Provisional asset label (D-03/D-04, hero illustration) | "Imagem ilustrativa — foto real em breve" — rendered at Label size (14px/600) in Oliva on the hero's dark background, near the illustration, never presented as if it were real product photography |
| Destructive confirmation | Not applicable — this phase has no destructive (delete/cancel/irreversible) action; every CTA either navigates, opens an external app, or is inertly disabled pending confirmation. |

All exact wording above other than the three locked HERO-02 labels is **Claude's Discretion per
CONTEXT.md** ("Redação exata do texto 'em breve'... fica a critério de quem escreve o copy final")
— treat these as a strong, on-tone default, not a second lock; the copywriter may adjust wording as
long as it keeps the same problem+next-step / provisional-labeling shape and passes
`tone-of-voice.md` §5's hard rules (no invented hours, no invented urgency).

## UI Considerations

Applicable state considerations resolved: 5 covered, 1 backstop, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| Empty | Operating-hours list (LOCAL-03, `hours.schedule: []`) | ✅ covered | Empty schedule renders the fixed provisional notice from the Copywriting Contract above (heading + body), sourced from `getStoreInfo().hours`, never a blank space or an invented hour string. |
| Error / disabled | Order CTAs — iFood + WhatsApp (INTEGRA-03) | ✅ covered | While `confirmed: false`, both CTAs render the identical "(em breve)" disabled state (D-05/D-06); the INTEGRA-03 notice text points to the working "Como chegar" action instead of swapping in another live-looking order link. |
| Long-text | Hero headline + all three CTA labels | ✅ covered | tone-of-voice.md §3's mobile-width fit rule applies verbatim; no dynamically-generated copy exists in this phase, so no truncation/ellipsis mechanism is needed. |
| Zero-one-many | Service modalities list (LOCAL-02, `storeInfoSchema.modalities`) | ✅ covered | The schema models modalities as an array (currently 3: balcão/delivery/take-away) — render as a flexible wrapping list/chip row, not three hardcoded fixed-position slots, so the layout survives a future 1–3 item change without a code edit. |
| Populated | Hero image slot (D-03/D-04, illustrated composition) | ✅ covered | `next/image` slot is always populated (illustration today, real photo later) inside a fixed-`aspect-ratio` container — see below — so the "populated" state is the only state this slot ever has; no empty-image placeholder path exists or is needed. |
| Overflow | FAQ answer text length (CONT-02 copy, variable length per question) | 🧪 backstop | Recommend native `<details>`/`<summary>` (zero JS, expands to fit any answer length, keyboard/screen-reader accessible by default) — no automated visual test covers long-answer overflow yet; flagged as a backstop, not a verified truth. |
| Unresolved | "Ver cardápio" CTA target route | ⚠ unresolved | Phase 3 (the actual cardápio page) has not shipped yet, so this research cannot state what "Ver cardápio" links to (a stub `/cardapio` route, an in-page anchor, or another interim target). Planner must record an explicit assumption; this UI-SPEC only fixes the CTA's *label and visual tier* (secondary, accent-outline), not its destination. |

Hero image container contract (supports the "Populated" row and D-04's CLS-safety requirement):
fixed 1:1 aspect-ratio box (matches the existing square viewBox convention of
`public/brand/logo-icone.svg`), `next/image` with `fill`, `priority`, and an explicit `sizes`
attribute for the mobile-first breakpoints — swapping the illustration file for a real product
photo later is a file replacement only, never a container/CSS change.
