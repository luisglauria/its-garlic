<objective>
Close gap G-02-5: the entire brand palette and both type families are dead site-wide because every
token in `src/styles/design-tokens.css` mirrors itself inside the theme block, and the import order
in `src/app/globals.css` makes that self-reference win the cascade. The visible symptom the user
reported is a missing focus ring; the actual blast radius is a total brand-palette outage plus a
WCAG 2.4.7 failure.

This plan fixes the cause, not the symptom, and installs two guards so it cannot silently return.

Purpose: G-02-5 is the blocking prerequisite for G-02-4 (nothing about section separators is
observable while every background renders browser-default white) and it changes the metrics
G-02-2's layout work must be tuned against (restoring Anton/Manrope changes how many lines the
hero headline and subhead occupy). It ships first for both reasons.

Output: a compiled stylesheet in which all seven brand colours and both font families resolve, a
fast source-level guard in `npm test`, and a compiled-artifact checker runnable as `npm run verify:css`.

Not a tracer: this plan adds no new architecture and wires no new path. It is a surgical repair of
one already-wired layer, so it decomposes into repair-then-guard rather than a vertical slice.
</objective>

    An inline theme block holding the two next/font-backed families. Each one must reference a
    variable name that is DIFFERENT from the theme key it defines, with the previous literal stack as

    Manrope / Inter / sans-serif stack. The distinct name is the whole point: a theme key that reads a
    variable of the same name is the defect this task exists to remove, and the inline option is what
    makes the utility resolve the next/font value at the element instead of at the root.

    In `src/app/globals.css`, swap the two import statements so the framework import comes first and
    the project token sheet second. Leave the two explanatory comments and the `:focus-visible` rule

    resolves. Add one short comment above the imports recording WHY the framework must be imported
    first (the token sheet's theme block has to be emitted inside the framework's theme layer, ahead
    of any unlayered declaration), so the next person does not "tidy" it back.

    In `src/app/layout.tsx`, rename the two next/font `variable` values to the new distinct names

    changes — the html element still spreads both `.variable` classes. Update the file's header
    comment so it names the new variables and states that they are deliberately distinct from the
    `--font-display` / `--font-body` theme keys that consume them.

    - No custom property in the token sheet is defined in terms of a variable of the same name
      (a regex with a backreference over the stripped source, reporting the offending names).
    - The framework import appears at a lower index than the project token sheet import in
      `src/app/globals.css`.

      the names out of the CSS and assert against `layout.tsx`, so renaming one side without the other
      fails here instead of in the browser.

      declares with a literal value.
